# 分组管理

默认分组（ID 1）始终保留，不提供删除操作。

## 删除分组

分组菜单提供“删除分组”。弹窗明确列出只移除 DevStart 登记，用户必须输入完全一致的“删除分组”，再点击确认；不弹第二次确认。取消或关闭清空输入。

后端 `Service::delete_group` 与 `groups.delete` 共用事务：删除分组、项目及启动项在目录索引中的登记。不会将项目移到默认组，不访问删除项目源文件的接口，不删除磁盘上的项目目录、Git 仓库或原始启动脚本。历史日志及配置备份继续按既有保留策略管理，不作为当前登记加载。删除时仅停止该分组关联的运行实例（包含已核实并登记的外部实例）：先 SIGTERM，5 秒宽限后仍存活则 SIGKILL，确认退出后才移除登记。其他分组实例不受影响。关闭失败或配置并发变化时保留登记，提示具体实例与原因。有未保存的编辑时也会拒绝删除并给出原因。

## 重新扫描更新项目启动脚本

分组菜单触发后台扫描。扫描范围是分组下已经登记的各项目目录，不自动扩展到未登记的相邻目录。复用自动扫描的技术栈识别器，重新读取当前项目名称、启动脚本和端口。启动源仍相同时保留 ID、收藏、显示名称及说明；已删除源不再保留，新源生成新 ID。源文件和项目仓库只读。

所有项目扫描成功后一次发布配置。目录不存在、读取或解析失败、扫描期间目录索引被修改时拒绝整批更新，保留原登记。目录移动后须重新添加正确目录，不猜测项目的新位置。扫描不会执行脚本或自动启动服务。更新涉及的运行实例需先停止。

API：`groups.refresh {"id":2}`，完整参数与结果见 `api-schema.json`。API 不要求输入删除文字；文字确认属于 GUI 交互。

## 删除单个项目

项目标题右侧管理菜单提供“删除项目”。输入完全一致的“删除项目”后一次确认即可，不再弹第二次确认。共用登记删除协议，仅停止该项目关联的实例并移除该项目、启动项登记；同组其他项目、分组本身及磁盘源文件保留。停止失败、并发新增实例、配置变化或未保存编辑均明确报错，保留登记。API `projects.delete` 使用同一后端流程，无文字确认。
