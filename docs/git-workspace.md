# 三栏 Git 工作区

## 结构

左导航提供独立 Git 入口。主窗口第一栏始终列出已登记项目及当前分支；点击项目才显示第二、第三栏；列表分支为弱化说明，中栏分支按钮打开本地分支选择框。三栏可拖动调整宽度。

第二栏顶部显示项目、路径、当前分支、Update Project 和远程地址。文件变动按未跟踪、有变化、新文件、删除分组，点击文件打开单文件 Diff，右侧撤销图标需二次确认；下方提供提交备注、本地提交、推送远程及持续项目终端。历史记录的作者前有用户图标，作者后为弱化短哈希；日期当年省略年份，显示至分钟，悬停显示原始日期。

第三栏展示 HEAD 提交历史，包括备注、作者、时间及提交 ID，每页 50 条。未安装 Git、非仓库、空仓库及 detached HEAD 均有明确反馈。

## 后端边界

- git_workspace：共享的 Git 进程运行、仓库快照、分支及历史查询。同一真实仓库串行写操作，GUI 与 API 共用锁。
- git_actions：修改文件解析、diff、提交、推送、拉取、备份回滚与 Git 参数命令。所有操作基于参数数组，不拼接 shell；文件使用 literal pathspec。状态由 porcelain -z 解析，保留重命名及空格文件名；未跟踪目录按 Git normal 模式合并为目录项，避免为每个子文件重复输出路径。选中目录提交时会包含目录内全部文件。
- git_jobs：API 写操作立即返回任务编号，再查询 git.job；最多四个运行任务，保留最近十六个结果，不持久化。
- ui_git：只负责三栏布局、交互状态与后台请求展示，不推断仓库数据。

Git 表单与 git.* API 任务的工作目录定位到真实仓库根目录，项目子目录与共享仓库都按真实根目录操作。git.command API 支持引号但不解释 shell 管道或环境变量；界面中的持续 PTY 终端则按真实 shell 执行输入。用户身份、凭据和 hooks 沿用 Git 配置；失败会显示真实日志，不伪造成功。命令超时 120 秒，停止独立进程组；每个流输出上限 2 MiB，GUI 命令反馈最多保留 256 KiB。

## 写操作（当前行为）

- Commit 只提交已勾选的本地文件（含未跟踪文件），无需远程连接，不执行 Update。
- Push 只推送已有本地提交，不自动提交工作区文件。非快进拒绝时显示 Merge/Rebase 更新选项，用户选择后更新并重试一次；冲突会暂停，不强推。
- Commit and Push 是明确的组合操作：先提交选中文件，再推送。推送失败时本地提交仍保留。
- Update 点击立即执行仓库记住的 Merge/Rebase 方式（默认 Merge），不弹前置确认。先 Fetch，若远程已包含在当前 HEAD 中，返回“已经更新，没有任何变化”，本地文件不产生额外 stash。
- 需要更新时将暂存区、工作区和未跟踪文件保存为本次操作拥有的 stash。Git 原生合并不重叠改动；冲突不会自动选择远程或本地。恢复暂存区失败且工作区仍干净时，尝试恢复到工作区并明确提示暂存状态变化。
- Git 目录中的 `devstart-update.json` 记录恢复 stash 和阶段；重启仍可继续。Merge/Rebase 提供继续、终止；Rebase 可明确确认跳过正在重放的提交。终止后恢复原 HEAD 和保存的本地修改。
- 冲突文件双击或“解决”打开三栏工具：左为当前版本，右为传入版本，中间为可编辑结果，可查看共同基线。Rebase 明确显示左侧为目标基线、右侧为正在重放的本地提交；stash 恢复显示更新后分支与保存的本地改动。
- 可以接受任意一侧完整版本（包括删除、二进制）或编辑结果；应用前校验索引和工作副本版本，保存本次冲突备份，保存并暂存这一文件。残留冲突标记拒绝保存。完成全部文件后由用户点击继续。
- 远程新增文件与原本地未跟踪文件同名时，将碰撞转换为可审阅的 Git add/add 冲突。不会用远程文件悄悄覆盖新文件。
- 文件/历史 Diff 与已有分支 Merge 继续沿用。分支 Merge 先切换到目标分支，Rebase 则将当前分支重放到选定本地分支之上，均不自动推送。
- Git 自身无法完成恢复且没有可处理的冲突时，显示真实错误和 stash 标识，允许用户检查并手动恢复后明确结束恢复；保留原 stash。应用仅清理自己已恢复且仍处于栈顶的 stash，不删除用户其他备份。
- 单文件回滚需二次确认，恢复前保存补丁备份。所有项目文档、恢复协议说明均在 docs 中；Git 内部恢复记录和冲突备份位于 Git 元数据目录，不进入提交。

架构：`git_integration` 负责操作生命周期与恢复状态，`git_conflicts` 负责三方版本与审阅后写入，`git_remotes` 负责远程选择、Fetch 和 Push，`git_actions` 负责单独 Commit。UI 仅收集选择、编辑文本并显示后端结果。Git 内部调用 Stash/Merge/Rebase 时不启用全局 literal-pathspec 参数，避免 stash 内部 clean 的根路径表达式失效；直接文件操作继续使用字面路径保护。

验证：独立临时 Git 仓库覆盖 Commit 离线、Push 不夹带未提交文件、推送拒绝、Merge/Rebase 更新、继续/终止/跳过、旧 stash 保留、新文件碰撞、删除/二进制选择、文本末尾换行和过期编辑拒绝。用户实际项目不用于制造测试冲突。

2026-10-26 最终验证：私人版 `cargo test` 与开源版 `cargo test --no-default-features` 均 192 项通过（包含 14 项 Git 工作流回归），两版原生 macOS 发布包构建成功。独立 QA 工作空间验证三栏冲突界面、共同基线、选择一侧并应用后仅暂存、继续 Merge、Rebase 更新无变化提示；拒绝带冲突标记的结果时保留未保存编辑。私人版已重新启动，开源版与 QA 实例退出。

流程依据：[IDEA Git 设置](https://www.jetbrains.com/help/idea/settings-version-control-git.html)、[提交与推送](https://www.jetbrains.com/help/idea/commit-and-push-changes.html)、[冲突处理](https://www.jetbrains.com/help/idea/resolve-conflicts.html)。对齐 Update/Commit/Push/Merge/Rebase 的操作职责与冲突审阅，不承诺复制整个 IDE 的功能或界面。

## 持久项目终端

分支名使用弱化灰色，仍可点击切换。中栏命令区替换为 project_terminal 管理的持续 PTY shell：默认目录是项目目录，不强行切到 Git 根目录；同项目会话保留 cd 与环境。后台实时读取输出，后端清理控制序列、识别提示符和退出码；UI 仅显示快照、发送输入和快捷键。命令完成后刷新 Git 信息。

Enter 执行、上下键调用历史、Ctrl+C 中断前台进程。密码回显关闭时输入遮蔽且不记历史。缓存最多 256 KiB / 3000 行、100 条历史、8 个会话。关闭应用或移除项目先 HUP/TERM，2 秒后强制结束仍存活的进程组。使用系统 PTY 与已有 libc，无新增依赖。行式交互不提供全屏应用屏幕仿真。

终端验证：完整 137 项测试通过；专项测试覆盖项目目录、持续 cd、实时输出、Ctrl+C、历史与缓存限额。实际 UI 验证 Enter 执行、上下键历史、git log 和连接隔离本地上游的 git pull，反馈 Already up to date。无个人项目参与 Git 写操作。

## 分支、远程与历史层级

第一栏项目名下紧贴弱化的分支说明，文字不可点击。第二栏信息头展示分支和分支切换图标、远程地址下拉及带符号的 Update。远程列表来自后端，涵盖同名 remote 的多个 fetch 地址；选择不会改写项目 Git 配置。Update 与推送都明确使用所选地址、当前分支，并校验目标未过期。推送确认框列出地址与分支，Update tooltip 说明从所选远程当前分支获取并合并。

历史栏默认宽度 350，最小 260，可拖动调整；每条完整提交记录使用交替的轻微背景，深浅主题分别调色，不以大量分割线分隔。

远程与布局验证：139 项测试通过，包括同名远程多个地址、跨远程更新（与原 upstream 不同）、过期分支/地址保护、URL 脱敏。使用隔离仓库检查第一栏的分支为非按钮文字、信息头的分支切换与远程选择、Update 确认，以及加宽的交替背景历史记录。

## 运行页的启动日志与终端

标签模式的项目信息区在原有命令预览行右侧提供“启动日志 / 终端”，默认是启动日志。切换只改变显示，不停止进程或日志接收。每个 Console 的选择在当前应用会话保留；终端以登记项目目录而非启动命令的 cwd 打开，与 Git 页共享同一项目的 PTY 后端。两处共用 TerminalView 控件，历史、输入、中断和缓存上限一致。

平铺模式及独立日志窗口仍使用原日志视图。已删除项目的旧记录无法打开终端时显示明确错误，不推测其他目录。关闭启动记录不结束项目终端；项目移除或应用退出时按既有终端生命周期关闭。

运行页双视图验证：140 项测试通过。隔离界面确认默认启动日志、右侧两个切换项、全高终端、项目目录提示符及 pwd/Git 命令回显；在终端视图停留时 logs.search 的实时日志数仍持续增长，切回日志后继续跟随最新输出。共享 TerminalView 的重构未新增另一套执行协议。

## 终端颜色

终端广告 xterm-256color / truecolor，并保留生产程序的 SGR 前景色、粗体、斜体与下划线。重用现有 ANSI 解析器，按流维护状态，兼容控制序列跨读取块及重置。非 SGR 光标/OSC 控制仍由行式终端处理，不把控制码打印到界面。

提示符绿色、用户输入蓝色、常规输出使用中性色。无自带颜色的明确 error/fatal、warning、hint/info、success/READY/Already up to date 前缀按固定格式映射颜色；不对任意语句猜测含义。自带 ANSI 颜色优先。浅色主题对低对比颜色作保色相的对比度调整。

颜色、提示符与输入回显的范围由后端标记并随缓存一起裁剪，前端只渲染 segments。样式缓存有上限，普通文本仍受 256 KiB / 3000 行约束。Git 页与运行页共享显示组件，因此同步生效。

颜色验证：142 项回归测试通过，实测 PTY 产生 ANSI 颜色后 segments 能完整还原纯文本，输入/提示符/警告/错误角色正确。深浅主题截图均确认真实输出与正在输入的命令配色清楚；缓存及交互行为沿用既有上限。

## 提交浏览布局

单击任意历史提交后隐藏工作区，保留项目栏，将历史列表移到中间，右侧展示所选提交的文件列表。选中历史有清晰边框，保留交替背景及分页；双击文件复用 unified diff 弹窗，标题显示提交短哈希与文件路径。返回工作区不重启终端或服务。

git_commit 后端直接读取 Git 对象：初始提交相对空目录，合并提交相对第一父提交，UI 明确显示比较基准。列表支持 A/M/D/R 及重命名前路径，diff 只读取属于该提交的文件，不使用当前工作区内容，不执行外部 diff/textconv。API 同步提供 git.commit_files 与 git.commit_diff。

提交浏览验证：145 项测试通过，新增用例确认初始提交、重命名、删除、二进制及合并提交的文件/diff 正确；读取历史时保持工作区和当前分支不变。完整提交 ID 与父提交元数据均校验，文件只接受该次提交返回的成员路径。

界面联调确认：单击提交后工作区隐藏，历史移至第二栏，第三栏显示本次提交文件；双击 Java 文件分别展示 1.0→1.1 与 1.1→1.2 的真实历史差异，返回工作区后原终端仍在。验证仅使用隔离仓库。

## 文件名与多文件 Diff

提交文件列表只展示文件名，悬停显示仓库中的完整绝对路径；重命名同时显示旧路径与新路径。`git.commit_files` 的文件记录新增 `file_name`、`full_path`、`tooltip`，原 `path` 继续作为精确文件标识。

Diff 使用非模态、可移动和缩放的窗口，右上角关闭。连续双击文件会添加文件名标签；相同项目、版本和路径复用同一标签，不同目录同名文件保持独立，悬停可区分完整路径与版本。窗口最多保留最近十个文件。每个标签提供关闭按钮与右键“关闭标签”；关闭当前标签切换到相邻标签，关闭最后一个标签隐藏窗口。右上角依次提供最小化、最大化/还原、关闭图标。最大化占满应用内容区域，正常窗口的尺寸与位置独立保留；还原返回原窗口。最小化保留标签并隐藏窗口，双击文件时恢复；右上角关闭窗口会清空全部标签并释放 diff 缓存。

后端将 Git unified patch 解析为带旧/新行号的只读行模型；前端只渲染。删除行采用低饱和红色背景和减号，新增行采用绿色背景和加号，上下文保留中性色，分段及文件元数据使用弱化蓝色背景。行号在每段按 Git hunk 重置，缺失结尾换行标记不占用行号。二进制差异和重命名元数据按 Git 原文展示。采用虚拟滚动，沿用 Git 输出 2 MiB 上限；查看不会修改仓库或工作区。

项目列表的项目名与弱化分支采用紧凑双行布局，采用两行纯展示文本与统一容器点击区域，避免默认按钮高度拉大两行间距。项目名、分支名及条目空白均选中同一项目；分支继续弱化显示，切换分支仍通过项目信息区按钮完成。

## 项目切换性能

Git 工作区使用后端 `snapshot` 一次生成展示模型，分支、远程、变更及历史独立并行读取；变更列表和历史首条同时提供项目概要，避免重复 status/log。历史翻页另取 HEAD 元数据，不能误把当前页首条当作最新提交。命令等待采用 1–20 ms 递增轮询，保留原 120 秒期限、2 MiB 输出限制和错误处理。

项目首次选择立即展示列表中已有的名称、路径与分支，详情后台读取。最多缓存八个已访问工作区，再次选择先显示缓存并强制刷新；刷新期间写操作禁用，失败明确显示错误，不把缓存当作最新状态。项目路径与分页必须匹配才能复用。提交、切换分支、更新以及终端命令结束后的详情读取都更新缓存。

隔离仓库对照：串行参考路径 447 ms，并行 snapshot 97 ms（约减少 78%）；该数字只代表测试环境。测试验证未提交文件、空仓库、历史翻页与 HEAD 版本的一致性。运行日志记录 project id、分页、耗时和成功状态，不记录远程凭据。

后台请求完成会主动唤醒界面绘制，避免额外等待 100 ms 定时帧。147 项回归测试通过，Clippy 无警告。

提交历史的所有条目右侧统一显示弱化右箭头，整条记录仍为同一个点击区域。项目页为分组、项目及启动项操作列统一预留额外 15px 右侧空间，避免与覆盖式滚动条重叠。


## 紧凑仓库工具行

项目信息只保留名称、路径和工具行。工具行依次为 Git 分支图标、当前分支下拉、更新图标、当前选中的远程地址；不显示 HEAD 版本号及最后提交人/时间。提交作者、日期和版本仍在历史记录中。

分支下拉选择后沿用仓库切换二次确认与工作区校验。更新图标点击立即执行，不二次确认，向当前选中远程的当前分支拉取并合并。

点击远程地址在居中弹层展示当前目标及已有远程地址，单选后确认，再二次确认切换。取消或关闭弹层不改变选择。目标仅影响 DevStart 当前应用会话中该项目的更新/推送，不改写 `.git/config`，不增加或替换 URL，不自动请求网络。选择前校验项目身份与可用目标，执行更新或推送时后端再次校验分支和目标是否仍存在。只有一个地址时可以查看，但无需重复切换。

工具行更新按钮显示向下箭头与 `Update Project`；提交本地使用 Git 提交节点图标，推送远程使用上传图标，提交文件标题使用清单图标，返回工作区使用左箭头。沿用原确认与仓库操作语义。

提交文件名之前展示 Git numstat 的绿色新增行数和红色删除行数，每次提交用一次批量查询，避免逐文件启动 Git。二进制文件返回 null/null 并显示“二进制”，纯重命名显示 +0/−0；初始提交与合并提交沿用原对比基准，API 同时返回 additions/deletions。NUL 分隔解析保留文件名中的制表符和换行。

## 本地分支合并

分支行右侧提供合并分支按钮，居中窗口选择来源与目标，居中确认/取消；确认后再次明确合并方向。后端单仓库写锁覆盖目标切换和合并，拒绝脏工作区、同分支、失效分支及进行中的 Git 操作；冲突保留现场，停留在目标分支，无自动推送。结果复用右下角常驻通知。支持 git.merge API，同样使用后端实现。

160 项测试通过；隔离 Demo 仓库实测选择、二次确认、成功合并及常驻通知，不操作真实项目分支。

## 恢复历史版本为本地最新版本

提交文件页提供“恢复到当前版本”，二次确认后将选中提交的完整文件树恢复并创建新的本地提交；保留历史和 refs/devstart/version-backups 下的原 HEAD 引用，不直接移动远程引用，不强推。要求干净工作区、无进行中的 Git 操作，确认的分支/HEAD 未发生变化；拒绝覆盖忽略文件碰撞。提交失败保留暂存状态并在常驻结果通知中说明，用户可检查现场。后续推送遵循现有更新/提交/推送流程。git.restore_version API 使用同一实现。

文件预览 tooltip 统一为两行：双击查看、完整绝对路径；路径保持一行，不显示 Git 原始状态码。工作区与历史文件均双击打开 Diff。

文件变动各状态分组默认展开，点击标题或箭头可收起/展开。折叠状态按项目与分组独立保存于界面状态，不影响文件勾选或实际 Git 状态。

文件变动列表使用独立占位的滚动条，内容与滚动条间隔 10px，避免滚动条覆盖右侧撤销按钮及其点击区域。该样式仅作用于文件变动列表。

回滚图标有至少 32×28px 的命中区域和明确控件名称；可回滚文件点击进入二次确认。未跟踪文件没有 HEAD 版本，保持禁用；使用单独的仅悬停区域显示原因，不提供误导的小手或点击行为。后台任务进行中会提示稍候。

## 本地 AI 提交备注与默认全选

文件变动默认全选，刷新保留手动排除；备注旁魔术按钮使用已安装并登录的 Codex/Claude/Cursor 命令行工具生成可编辑备注。仅将已选且非冲突的文件提供给生成器；其他文件的冲突不阻止生成。设置可选择首次自动发现并记住、每次自动检测或固定工具；固定工具失败不换用其他工具。生成不执行提交。详见 [本地 AI 提交备注](ai-commit-messages.md)。

文件变动标题提供总全选复选框，各状态分组提供组内全选；支持全选、未选及半选状态。总全选覆盖已收起分组，取消后刷新保留取消状态。所有批量选择由 git_selection 后端维护，与逐文件勾选和 AI 备注生成使用同一集合。

合并选择与确认框按当前来源/目标动态说明影响：来源分支不变；目标接收提交、更新本地文件，必要时生成合并提交；工作区停留在目标分支，同仓库其他项目可见文件变化；远程不变，冲突保留。说明不针对 main 做特判，反向选择时仍如实提示。

合并来源与目标相同时，点击确认会在弹窗内明确提示“合并分支不能两个相同的分支合并”，不进入二次确认或执行 Git 操作；修改为不同分支后清除错误。UI 和 API 执行共用后端校验。

Console 的项目终端在平铺和标签视图均可切换，默认显示 Console 启动日志。终端使用项目目录和已有 PTY 服务；切换不清空日志或终端历史。空间足够时开关位于状态/命令行右侧，窄卡片换行保留访问入口。平铺卡片点击后显示蓝色内边框，激活不覆盖子控件的选择、点击或输入事件。

## Update 直接执行

Update 按钮直接提交后台更新任务，移除每次出现的更新方式选择弹窗。Fetch 后由 Git 尝试自动合并；无变化、成功更新或自动合并通过现有结果浮层反馈。仅无法自动合并的冲突进入现有冲突处理流程，本地恢复备份继续保留。网络、权限等失败保留真实错误，不误报为冲突。独立 Rebase 操作保留显式选择。
