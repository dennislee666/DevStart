# Console 与运行实例身份

## Root Cause

原先仅 `restart_checked` 迁移 Console 身份；普通 `launch_checked` 和外部 `adopt` 每次都创建新的 `console_id`。已结束的旧实例仍然开放标签，所以连续启动、停止或外部重新启动会累积平铺卡片、标签和会话列表。独立窗口还以运行实例 ID 保存窗口状态，需随实例迁移。

## Architecture Design

- `Run.id` 是一次进程运行的唯一身份，负责事件、停止句柄与独立日志文件。
- `Run.console_id` 是一个逻辑启动项/外部服务的稳定展示身份，负责标签及原生窗口。
- `Runtime::rebind_console` 统一绑定新运行实例到现有 Console，原有运行标记为 superseded 并关闭旧标签，保留原控制器、事件 ID 和日志。
- 普通启动按稳定的启动项 ID 复用。外部服务重新识别按规范化工作目录、监听端口和关联启动项交集匹配已结束实例；同一个 PID 与进程身份重复发现是幂等的。
- 外部服务与已确认关联的受管启动项可共享 Console；不同目录、不同端口或不同启动项保持独立。不会按显示名称猜测服务身份，也不会把同时存活的不同外部进程隐去。
- `Service::current_console_generation` 提供当前展示实例，UI 仅读取该结果。独立窗口字典及 viewport 使用稳定 Console ID，活动标签在实例切换后保持原选择。

## Execution Plan / Implementation

1. 让普通启动、显式重启和外部识别复用同一个后端绑定函数。
2. 优先复用当前显示的 Console 位置；隐藏被替换的旧代，保留独立日志和进程控制。
3. 独立窗口使用 Console 身份，移除按运行实例迁移窗口状态的逻辑。
4. 保持原启动前校验、停止旧进程及失败恢复流程；启动检查失败但原服务仍运行时，恢复原服务的可见 Console。
5. 历史继续按现有限额保留；被替换的旧代不能再打开成重复标签，磁盘日志由原保留策略管理。

## Verification

独立临时进程覆盖：自然退出、停止后再启动、重复启动点击、关闭后再启动、失败后再启动、超过历史限额的多代更新、外部同端口连续重启、同 PID 重复识别、不同端口保持分离，以及旧代日志/停止动作不影响新代。

旧的“允许普通启动产生两个标签”测试已调整为当前行为，并保留人工构造旧版重复标签后的兼容收敛检查。

2026-10-26：私人版 `cargo test -- --test-threads=2` 198 项通过，开源版 `cargo test --no-default-features` 198 项通过，包含新增 6 项身份复用测试与原有 7 项重启回归。两版原生 macOS Release 打包通过。两套高并发测试同时运行时，一项强制停止/进程复核用例触及既有 12 秒等待上限；该项独立运行通过，私人版降低测试并发后完整通过，未放宽产品或测试超时。

隔离原生 GUI：同一脚本普通启动三次后只有一张平铺卡片、一个标签、一个会话入口；打开独立窗口后第四次启动仍使用同一原生窗口，PID 和日志更新、Console 身份不变。外部服务连续重启三次、不同端口隔离及旧代事件隔离由真实临时监听进程回归覆盖。

私人版已重新加载修复，重启前的受管官网服务已恢复运行，外部 Java 服务保持原进程。开源版和临时 GUI 验证实例均保持退出。

## Reflection

复用的是逻辑视图身份，进程实例和日志仍逐次隔离。该机制同时适用于脚本、Java、Package 等已有启动类型，不按项目名称、语言或某个业务服务做特判。
