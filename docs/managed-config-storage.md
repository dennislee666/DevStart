# DevStart 启动配置托管存储

## 目标与边界

项目注册、分组、收藏、别名、简介、命令参数和端口配置只写软件用户数据目录。业务目录用于读取原有启动文件、解析路径和作为进程工作目录；不创建 `.dev-start.json`、不编辑 `.gitignore`、不操作业务 Git 索引或提交。编辑器保存/回退原代码及启动命令自身的文件写入仍属于用户显式项目操作。

## 最终目录与权威来源

```text
<DevStart 用户数据目录>/
├── catalog.json                      # version=2；稳定ID、分组、展示元数据、执行缓存
├── projects/<project_id>/
│   └── .dev-start.json                # version=1；该项目全部登记启动定义
├── migration-backups/managed-config-<id>/
│   ├── catalog.json                  # 原索引精确字节备份
│   ├── project-<project_id>.json      # 原项目清单精确字节备份
│   ├── plan.json                     # 来源位置、备份对应关系
│   └── completed.json                # 迁移完成记录
├── logs/                             # 有界日志，沿用既有配额
└── source-versions/                   # 启动源文件版本，沿用既有配额
```

个人版 macOS 默认目录为 `~/Library/Application Support/dev-start`；开源版为 `~/Library/Application Support/devstart`。显式 `DEV_START_DATA_DIR` 可改变工作空间，GUI、CLI、headless、MCP 必须使用相同目录。配置不写进 `.app` 安装包或源码仓库。

托管清单负责启动定义，catalog 缓存用于稳定ID与运行时引用，不作为清单缺失时的恢复来源。加载时必须有合法清单，刷新从清单重建执行快照；Java启动前再次校验清单快照。用户应通过 API 变更配置，手动编辑清单后需刷新。相对 file/cwd/classpath 仍相对业务项目实际路径解析，与清单存放位置无关。

## 写入事务

Service 是唯一配置所有者。所有配置入口（UI、API、CLI、MCP、profile）复用 Service 提交路径。先解析、校验与准备内存副本，再按项目 ID 生成托管清单及目录索引。配置事务先持久化旧字节日志，再原子替换目标文件；全部成功后删除事务日志。失败会恢复原字节，不提交内存副本。启动时先恢复未完成的事务，之后才加载配置。托管相对路径拒绝路径穿越和符号链接，防止写入重定向到业务项目。

## 新项目与重新读取

新项目只读发现 package.json 和按协议命名的 Shell/Python 入口，登记后立即在软件数据目录创建清单。自动发现模式的刷新继续扫描项目已有入口，保留用户参数、收藏、显示信息及自定义预设。通过 scripts.create/update/delete 明确维护后，项目进入显式清单模式；刷新只读取托管清单，不重新附加已删入口。

Java与其他复杂入口通过明确的配置登记，不依赖 VS Code/Cursor 或项目中的 DevStart清单。需要已有的依赖、主类和工具链；该规则不授予部署、上传等任务额外执行权限。

## 旧数据的一次性迁移

仅 catalog.version=1 触发，不是日常运行时的兼容分支：

1. 精确备份原 catalog 及已有的各项目根目录旧清单，保存在软件目录。
2. 使用现有登记数据生成托管清单，把 Java 清单路径与快照重新绑定到软件目录。保留ID、组、收藏、别名、描述、参数、环境变量、端口、禁用状态与编辑历史关联。
3. 持久化清理计划，通过配置事务发布托管清单和 version=2 索引。
4. 只删除与备份逐字节一致、属于原登记项目的旧 `.dev-start.json`。不修改业务源码及 Git 配置。
5. 保存完成记录后删除工作空间中的待处理计划；中断后会继续该计划。发生文件变化、无权限或存储失败时明确报告原因，保留备份与计划。

version=2 只接受最终托管位置。损坏或缺失会报错，不读取业务项目中的同名文件补齐。未登记项目里的同名文件不属于本次迁移，不会擅自清理。

## 验证

覆盖独立项目/软件目录的完整注册与API增删改、Git状态前后相同、忽略业务目录同名文件、自动发现新增入口、显式删除不重生、原ID与别名收藏保留、精确备份及旧清单移除、失败保留原数据、崩溃事务恢复、符号链接写入拦截。另执行完整测试、格式检查、clippy、真实 headless API 和 Java 编辑器验证。
