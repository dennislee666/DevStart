# 项目分节表格与标题操作

## Root Cause

具体分组已支持项目分节，但“全部”仍按启动项平铺。项目标题缺少管理入口，项目和分组操作混在每个启动项行末，导致查找和管理入口重复。

## Architecture Design

后端 `LaunchTableContent` 明确提供平铺行或项目分节。`LaunchProjectSection` 保存项目身份、名称、路径和经过搜索/排序的启动项。UI 不自行归组、筛选或重新排序数据。

## Implementation

- 项目页面的“全部”和具体分组均使用项目分节；收藏保持原平铺表格。
- “全部”按组名、项目排列，第一列为“组名 / 项目”；具体分组的第一列为“项目”。后续均为启动项、启动命令、状态、端口、操作。
- 项目名称（“全部”带组名）和弱化路径只在标题行出现一次，启动项行第一列留空。空项目只显示标题。
- 每个标题行最右侧固定提供项目菜单和分组菜单。启动项行只保留启动项操作，项目操作不再逐行重复。
- 项目菜单复用重命名、重新读取/添加脚本、打开目录、收藏/取消收藏、移动分组、删除。分组菜单提供向此组添加项目、重命名、重新扫描、删除；默认组删除保护和原有删除确认保持生效。
- 菜单目标由后端分节元数据提供，空项目与同名项目也按稳定 ID 定位。
- “全部”以组名为外层顺序，项目排序在各组内生效；状态/端口排序在项目内生效。具体组默认按项目正序，排序箭头与实际顺序一致。

## Verification

后端专项回归覆盖分组边界、空项目、同名项目、搜索、收藏保持平铺，以及项目排序和项目内端口正序/倒序。

2026-10-27：两版项目分节回归各 3 项通过，覆盖“全部”的组名/项目顺序、具体组项目内排序、菜单目标元数据、空项目与同名项目。英文 UI 文案完整性回归通过。两版原生 macOS Release 构建通过。隔离 GUI 确认“全部”默认展示组名/项目分节，每个标题右侧都有独立项目与分组菜单；项目菜单覆盖重命名、重读/添加脚本、目录、删除、收藏和移动，分组菜单覆盖添加项目、重命名、重新扫描和删除；向分组添加项目时自动预选正确分组，默认组不显示删除。具体分组保持项目标题和双菜单，空项目同样有操作入口。私人版已重新加载，原有 Starter 与官网本地分别恢复监听 8082 和 3000；开源版及临时 QA 实例退出。

## Reflection

复用原有启动项单元格、状态胶囊、端口及操作按钮，项目标题统一承载组名、项目元数据和管理入口，启动项行仅承载启动操作。
