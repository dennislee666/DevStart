# 分组筛选后的项目分节表格

## Root Cause

列表原本只提供平铺启动项行。选中单一分组后仍在每行重复组名、项目名和路径，无法通过项目标题组织同一项目的启动项。

## Architecture Design

后端 `LaunchTableContent` 明确提供平铺行或项目分节。`LaunchProjectSection` 保存项目身份、名称、路径和经过搜索/排序的启动项。UI 不自行归组、筛选或重新排序数据。

## Implementation

- 仅“项目”页面选中具体分组时使用分节模式，移除组名列。
- 列顺序为：项目、启动项、启动命令、状态、端口、操作。
- 每个项目单独显示一行标题；项目名称和弱化路径在第一列，其他列留空。后续启动项行第一列留空，启动项显示在第二列。
- 无启动项的项目只显示标题，不额外创建占位启动项或操作按钮。
- 项目名排序调整项目分节顺序；状态/端口排序在项目内部生效。默认隐藏的“组名”排序映射为项目正序，排序图标与实际排序保持一致。
- “全部”及收藏继续使用已有平铺表格、原列顺序及排序语义。按稳定项目 ID 归组，同名项目也不会被错误合并。

## Verification

后端专项回归覆盖分组边界、空项目、同名项目、搜索、收藏保持平铺，以及项目排序和项目内端口正序/倒序。

## Reflection

复用原有启动项单元格、状态胶囊、端口及操作按钮，只为具体分组增加项目标题行。分节标题无额外操作或信息，减少重复内容。
